1세션 시작 — 1회차 이어받기

클로드 코드에 아래를 그대로 붙여넣으세요. HTML 파일 하나만 있으면 어느 컴퓨터에서든 작업을 이어갈 수 있습니다.

💬 클로드에게 붙여넣기 
이 폴더에 index.html 파일이 있어. 1회차 수업에서 만든 회사 홈페이지야.
파일을 읽고 어떤 사이트인지 파악한 다음, 로컬에서 브라우저로 열어서 보여줘.
이제 이 파일에 기능을 추가하는 작업을 이어서 할 거야.

2깃허브에 코드 올리기

🙋 뭘 해야 할지 모르겠으면 — 먼저 물어보세요 
지금 만든 홈페이지를 깃허브에 올려서 백업해두고 싶어.
깃허브는 처음이라 계정도 없어. 명령어는 내가 직접 안 치고 올리는 건 네가 다 해줘.
계정 만들기부터 순서대로, 내가 브라우저에서 할 일만 쉽게 알려줘.

클로드가 "계정과 저장소만 만들어 주시면 올리는 건 제가 합니다"라고 답합니다 — 여러분이 할 일은 아래 브라우저 작업이 전부예요.

  1. github.com 접속 → 오른쪽 위 Sign up → 이메일·비밀번호 입력, 인증 메일 확인하면 계정 완성
  2. 로그인된 화면에서 왼쪽 위 New 버튼
  3. Repository name 입력 (예: homepage) → Public 선택
  4. ⚠️ "Add a README" 등 체크박스는 전부 해제 (빈 저장소여야 함)
  5. Create repository → 화면에 뜨는 https://github.com/계정/이름.git 주소 복사
💬 클로드에게 붙여넣기 (주소는 내 것으로 교체) 
이 폴더를 git 저장소로 만들고 깃허브에 올려줘.
저장소 주소는 https://github.com/계정명/저장소이름.git 이야.
로그인 창이 떠도 놀라지 마세요. 첫 푸시 때 브라우저로 GitHub 로그인 창이 한 번 뜹니다. 로그인하면 그다음부터는 자동이에요.

끝나면 깃허브 페이지를 새로고침 — 내 파일이 올라가 있으면 성공! ✅

3개념 잡기 — "배포"가 뭐예요?

지금 홈페이지는 내 컴퓨터에만 있어요. 주소창이 file:///로 시작하면 나만 볼 수 있다는 뜻입니다. 남들이 보려면 24시간 켜져 있는 컴퓨터, 즉 서버에 올려야 하고 — 그게 배포(Deploy)입니다.

내 컴퓨터🍳 주방 — 요리(수정)하는 곳. 나만 봄 (file:///)
깃허브📦 레시피 보관소 — 코드 저장 + 버전 기록 (세이브 포인트)
넷리파이🍽️ 식당 — 전 세계 누구나 접속 (https://)

4넷리파이로 배포하기

🙋 뭘 써야 할지 모르겠으면 — 먼저 물어보세요 
깃허브에 올린 홈페이지를 넷리파이(Netlify)라는 무료 서비스로 진짜 인터넷 주소에 배포하고 싶어.
나중에 API 연동 기능도 붙일 거야. 어떤 순서로 하면 되는지 쉽게 알려줘.

넷리파이를 콕 집어 말하는 이유 — 그냥 "배포해줘"라고 물으면 깃허브 페이지스를 추천받기도 하는데, 거기엔 나중에 붙일 API 기능(서버 함수·환경변수)이 없습니다. 순서는 아래에 정리돼 있어요.

4-1. 수동 배포 (드래그 앤 드롭)

  1. netlify.com 로그인 → Projects 화면 맨 아래 "Drag and drop your folder here" 상자 (안 보이면 주소창에 app.netlify.com/drop)
  2. index.html이 들어있는 폴더째로 화면에 드래그 (⚠️ 파일 말고 폴더!)
  3. 몇 초 뒤 https://랜덤이름.netlify.app 생성 — 내 사이트가 인터넷에 떴다! 🎉

이제 수정을 해보면...

💬 클로드에게 붙여넣기 (주소는 방금 만들어진 내 것으로 교체) 
방금 이 홈페이지가 https://랜덤이름.netlify.app 주소로 인터넷에 배포됐어.
페이지에서 바꿀 곳은 네가 하나 골라서 문구를 살짝 바꿔줘. 로컬에서만 수정해.
앞으로 깃허브에 올리는 건 내가 따로 알려줄게.

사이트를 새로고침해도 안 바뀌죠? 수동 배포는 수정할 때마다 폴더를 또 끌어다 놔야 합니다. 귀찮죠. 그래서 →

4-2. 깃허브 연동 (자동 배포)

  1. 넷리파이에서 Add new project → Import an existing project → GitHub
  2. 아까 만든 저장소 선택 → 설정 그대로 Deploy
  3. 배포 완료되면 링크 클릭해서 확인 (연습용 드롭 사이트는 지워도 됨)
💬 클로드에게 붙여넣기 
아까 수정한 거 깃허브에 올려줘.

잠시 후 사이트 새로고침 — 넷리파이를 안 건드렸는데 사이트가 바뀌었죠? 이게 자동 배포입니다.

깃허브를 쓰면 이게 편합니다 — 넷리파이(식당)가 내 깃허브(레시피 보관소)를 계속 지켜보고 있다가, 새 버전이 올라오는 순간 알아서 사이트를 새로 만듭니다. 나는 클로드에게 "깃허브에 올려줘" 한 마디만 하면 배포 끝 — 폴더를 다시 끌어다 놓을 일이 없어요.

앞으로의 작업 방식:

국룰 워크플로우 — ① 평소엔 "로컬에서만 수정해줘"로 계속 다듬고 브라우저로 확인 (공짜·무제한) ② 완성되면 "깃허브에 올려줘" 한 마디 ③ 실제 사이트 자동 업데이트
크레딧 주의 — 무료 계정은 월 300크레딧, 배포 1번에 15크레딧(한 달 약 20번). 글자 하나 고칠 때마다 올리지 말고, 로컬에서 다듬고 한 번에 배포하세요.

5한국은행 API — 시장 지표 넣기

🙋 어떤 API를 쓸지 모르겠으면 — 먼저 물어보세요 
홈페이지에 기준금리, 코스피·코스닥, 원/달러 환율이 자동으로 표시되게 하고 싶어.
무료 API 중에 뭘 쓰는 게 좋을지, 키는 어떻게 발급받는지 알려줘.

한국은행 ECOS API를 추천받게 됩니다 — 키 1개로 네 가지가 전부 되거든요. 발급 순서는 아래에.

API란? 프로그램용 전화 창구예요. 우리 홈페이지가 한국은행에 "기준금리 알려줘"라고 물으면 기계가 읽기 좋은 형태로 답해줍니다. API 키는 출입증 — 비밀번호처럼 다루세요.

키 발급

  1. https://ecos.bok.or.kr/api/#/ 접속 (⚠️ 끝의 /#/까지 입력)
  2. 오른쪽 위 인증키 신청 바로 클릭 — 로그인/회원가입 화면이 자동으로 이어집니다 (처음이면 여기서 가입)
  3. 신청서 작성 (목적: 개인 학습용) → 보통 즉시 발급 → 마이페이지에서 키 확인
💬 클로드에게 붙여넣기 (키는 내 것으로 교체) 
한국은행 ECOS API 키를 발급받았어: (여기에 키 붙여넣기)
홈페이지에 기준금리, 원/달러 환율, 코스피, 코스닥을 보여주는
시장 지표 섹션을 추가해줘. 사이트 디자인에 맞춰서.
API 키가 코드에 노출되지 않게 안전한 방식으로 해줘.

환경변수 등록 (배포 전에 꼭!)

  1. 넷리파이 → 내 프로젝트 → Project configuration → Environment variables → Add a variable
  2. Key: ECOS_API_KEY / Value: 발급받은 키 → 저장
💬 등록 후 클로드에게 
깃허브에 올려줘.
"왜 로컬에서는 안 보여요?" — 지표를 가져오는 비서(서버 함수)는 넷리파이에만 있어요. 로컬에서 값이 "—"로 뜨는 건 정상. 배포된 사이트에서 확인하세요.

6구글시트 문의 폼

홈페이지에 문의가 오면 내 구글시트에 자동으로 쌓이게 만듭니다.

🙋 방법을 모르겠으면 — 먼저 물어보세요 
홈페이지에 문의하기 폼을 달고, 제출된 내용이 내 구글시트에 자동으로 쌓이게 하고 싶어.
서버 없이 무료로 되는 방법으로, 내가 구글에서 클릭해야 하는 것까지 순서대로 알려줘.

구글 Apps Script 방법을 알려줍니다 — 아래에 붙여넣을 코드까지 미리 준비해뒀어요.

구글 쪽 설정

  1. sheets.google.com → 빈 스프레드시트 → 1행에 시간 이름 연락처 문의내용 입력
  2. 메뉴 확장 프로그램 → Apps Script → 기존 코드 지우고 아래 코드 붙여넣기 → 저장(💾)
📋 Apps Script에 붙여넣기 
function doPost(e) {
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheets()[0];
  var p = e.parameter;
  sheet.appendRow([new Date(), p.name || '', p.contact || '', p.message || '']);
  return ContentService.createTextOutput(JSON.stringify({ result: 'ok' }))
    .setMimeType(ContentService.MimeType.JSON);
}
  1. 배포 → 새 배포 → ⚠️ 왼쪽 톱니바퀴에서 "웹 앱" 선택 (안 하면 URL이 안 나와요!)
  2. 실행 계정: 나 / 액세스 권한: 모든 사용자 ← ⚠️ 제일 많이 틀리는 곳
  3. 승인 과정에서 "확인되지 않은 앱" 경고가 떠도 정상입니다 (내가 방금 만든 앱이라 그래요) → 고급 → 이동 → 허용
  4. /exec로 끝나는 웹 앱 URL 복사 (창을 닫았으면: 배포 → 배포 관리에서 다시 확인)
💬 클로드에게 붙여넣기 (URL은 내 것으로 교체) 
구글 Apps Script로 문의 접수창구를 만들었어. URL은 이거야: (웹앱 URL 붙여넣기)
홈페이지에 문의하기 폼(이름, 연락처, 문의내용)을 만들어서
제출하면 이 주소로 전송되게 해줘. 로컬에서만 작업하고 아직 배포하지 마.

로컬 브라우저에서 폼을 제출해보세요 → 구글시트에 한 줄 추가되면 성공! (이건 로컬에서도 작동해요)

?막혔을 때 — 자주 나오는 문제

증상해결
깃허브에 push가 안 돼요브라우저에 GitHub 로그인 창이 떠 있는지 확인 → 로그인
드롭했는데 404가 떠요파일이 아니라 폴더째 드래그했는지, 파일명이 index.html인지 확인
Apps Script URL이 안 나와요새 배포에서 톱니바퀴 → "웹 앱"을 선택했는지 확인. 이미 배포했다면 배포 → 배포 관리
폼을 보내도 시트에 안 찍혀요Apps Script 배포의 액세스 권한이 "모든 사용자"인지 확인 (수정했으면 재배포)
시장 지표가 "—"로만 나와요① 로컬이면 정상 (배포된 사이트에서 확인) ② 배포했는데도 안 나오면 넷리파이 환경변수 ECOS_API_KEY 등록 후 다시 배포
"확인되지 않은 앱" 경고정상입니다 — 고급 → 이동 → 허용
사이트에 수정이 반영 안 돼요클로드에게 "깃허브에 올려줘"라고 했는지 확인 (로컬 수정만으로는 사이트가 안 바뀜)
그래도 안 되면 — 손 들고 부르세요. 에러 메시지를 클로드에게 그대로 붙여넣고 "이거 왜 안 돼?"라고 물어보는 것도 좋은 방법입니다.
